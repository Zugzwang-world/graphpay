# GraphPay event repo: rules for every Claude Code session

GraphPay, "Ask before you pay": AI agents with ENS names pay shops over x402 on Whitechain through our own facilitator; every payment becomes part of a money graph on Arkiv that any agent can ask, with an explain trace of every read, before it pays. Built at ETHGlobal Mumbai (Thu 5 Nov 21:00 IST → submission Sat 7 Nov 09:00 IST).

`planning/` is the pre-event knowledge pack, copied unchanged in the first commit. **Never edit it.** Every pack path in a prompt (`SPEC/…`, `FACTS.md`, `PROMPTS/…`) means `planning/<path>`. The event repo's own files are always named with their full path (`docs/technical/FACTS.md`, `docs/technical/WALLETS.md`). Where the pack and the event records differ, the newer event record wins: `docs/plan/` (amendments, acceptance additions, the master plan) and `docs/decisions/`.

## Hard limits (they hold in every mode, including bypass)

- **Testnets only:** Whitechain Sepolia 1874, Ethereum Sepolia 11155111, Arkiv Rabdi 7794095. Check `eth_chainId` before every signing step and refuse any other chain. Never mainnet funds.
- **Never read, print or commit secrets** (`.env*`, keystores, keys, tokens, keyed RPC URLs). Keys are generated by script straight into `.env`; scripts print addresses only. Environment variables are named, never shown. Never put a secret on a command line or in a URL you log.
- **Only operate on resources named `graphpay` or `graphpay-*`:** GitHub repos `graphpay` and `graphpay-lab`; Vercel projects `graphpay-event`, `graphpay-store`, `graphpay-lab`. Never list, change or delete anything else in the founder's GitHub, Vercel or Supabase accounts (never `vercel project list`).
- **No off-chain database** (ADR-0003): state lives on the Whitechain contract and Arkiv; Vercel only runs code. No Supabase, Redis or KV. No personal data.
- **No lab code** (ADR-0002, ADR-0015): everything here is written during the hackathon.
- **Never guess** versions, addresses, chain ids or API names: verify against a primary source and record it with source and date in `docs/technical/FACTS.md` or `docs/technical/VERSIONS.md`.
- **Synthetic data is always labelled.** No invented numbers. Say "tallies", never "rollups".

## Event rules decided at M0 (ADRs in `docs/decisions/`)

- **One config file:** `packages/config/graphpay.config.json` holds every person, shop and agent name (`cast`: tonight the pack's cast as the test cast, the final demo cast is added on Friday) and every ENS, Whitechain and Arkiv address and URL. Code reads names and addresses from it (through `@graphpay/config`); `pnpm check` fails on a known address literal anywhere else in code. Wallet env names stay the pack's; the cast binds each member to a wallet role.
- **Whitechain RPC:** `WHITECHAIN_RPC_URL` is a server-only secret (the founder's keyed Ankr URL). Fallbacks, in order: the public Ankr URL, then `rpc.testnet.whitechain.io`. Every candidate must answer chain id 1874 or it is refused. Never `NEXT_PUBLIC_`, never logged; log the candidate's label, not its URL.
- **A general Whitechain payments solution:** nothing is hard-coded to one prize track (the event enters Operate); track-specific wording lives only in the sponsor files and the submission text.
- **Node 22:** CI and Vercel run 22.23.4. This Mac's shell starts on Node 24 and does not run fnm's hook: run Node-sensitive checks with `fnm exec --using=22.23.4 <command>`.
- **Secrets in worktrees:** worktrees have no `.env`. Every script and service loads secrets through the git-based loader `scripts/lib/env-loader.mjs` (this checkout's `.env`, else the main checkout's if git ignores it there; `ENV_FILE` overrides and must be ignored too).
- **Booth questions:** no answers are coming; the founder's defaults are final (ADR-0032, ADR-0038…ADR-0044).

## How we work

- Every change goes through a PR into protected `main` (required check `ci`, squash only, auto-merge, linear history). **Force-push is denied:** rebase only before the first push; afterwards merge `origin/main` into the branch. Never merge on red or pending. Use the `ship` skill.
- Run the **reviewer** agent on every contract, payment, signature, key, secret or spending-endpoint change before it merges, and the **verifier** agent on every new version, address, chain id or API name. (New agents load after a restart; until then run a general-purpose subagent with the agent file's text as its prompt.)
- **Lockfile:** keep dependency changes in one early PR per package; on a `pnpm-lock.yaml` conflict take main's lockfile and re-run `pnpm install`.
- Records kept current: `docs/plan/MASTER_PLAN.md`, `docs/decisions/` (skill `adr`), `docs/problems/PROBLEM_LOG.md` (skill `problem`), `docs/technical/FACTS.md`, `docs/technical/VERSIONS.md`, `docs/technical/WALLETS.md`, `AI_USAGE.md`.
- `prompts/raw/` (the redacted prompt log the hook writes, one file per session and day) is committed with each PR; `.vercelignore` keeps it out of deployments.
- Write PR bodies to a file and run `git push` and `gh pr create` as separate commands.

## Thinking-partner folder (`docs/thinking-partner/`)

The founder's thinking partner (Claude on the web) knows only what this folder says, and it is the founder's single to-do list. **Its updates ride in the same PR as the step's work.**

| file | what goes in it |
|---|---|
| `NOW.md` | one page: updated time (IST), where we are in plain words, what's running, blockers, next. A short top summary (main only), then one fixed section per activity; each session rewrites only its own section at the end of every step |
| `relays/<activity>.md` | one per activity (`foundation`, `payments`, `identity`, `arkiv`, `agents`, `integration`, `website`, `records`, `submission`); about 800 words, plain language first, then technical; overwritten each step |
| `briefs/` | every brief the founder attaches, saved on receipt as `briefs/<HHMM>-<slug>.md`; a pack prompt gets a one-line pointer file instead of a copy |
| `LOG.md` | one line per PR: time (IST), activity, result, PR link; append-only under your activity's heading; only main rolls older lines up |
| `OPEN.md` | the founder's to-dos and open questions, each with what, where, why and a recommendation: "Founder now" at the top (main only), then one section per activity |

Rules: the folder stays under about 20,000 words (`wc -w docs/thinking-partner/**/*.md`). No secrets, no key-shaped strings, no private URLs; judge-safe wording, because the repo is public. Each session owns its own sections and its own relay. After the last push, watch the PR until it merges; on a conflict, merge `origin/main` again, keep every line, and push.
