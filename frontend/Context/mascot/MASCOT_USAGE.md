# Fox mascot: usage guide

How the fox should behave in the app. Source: [rive/](./rive) (`scene.rml`, generated by `rive/tools/gen_scene.py`). Build with `rive mascot\rive`.

Status: this is a design brief. The Rive file has five artboards and no triggers yet; the app-side wiring below is not built.

## 1. The animations we have

Each is its own artboard. Every one also runs the ear twitch, so the fox never looks frozen.

| Artboard | Length (60 fps) | Loops | What it says |
|---|---|---|---|
| `Wave` | 3.3 s | no | Hello. Happy eyes, open smile, paw waves four times. |
| `Smile` | 2.5 s | no | Pleased. Happy-arc eyes, open mouth, blush, little bounce. |
| `Blink` | 4.5 s | yes | Alive and attentive. One blink per loop. |
| `Idle` | 6 s | yes | Resting. Breathing, slight head and scarf sway. |
| `Squint` | 5 s | no | "What are you doing, bro?" Half-lidded stare at the user, one brow up, head cocked. |

## 2. Behaviour script

States the app moves the fox through. `Idle` (with `Blink`) is the home state; everything else returns to it.

1. **App opens → `Wave`** once, then settle into `Idle`. Play it on the first open of a session only, not on every screen change.
2. **After the wave → `Blink`/`Idle`.** The fox is now just present.
3. **Inactivity → `Squint`.** After 20 s with no tap, scroll, key or pointer movement (and no payment or agent run in progress), play `Squint` once. If still inactive, wait at least 60 s before playing it again, never back to back. Any input cancels it: ease back to `Idle`.
4. **Good news → `Smile`.** Play on a positive moment: a payment confirmed, an agent's check passed, a question answered. Also on the user's first interaction after a `Squint`, as a friendly "there you are".
5. **Keyboard opens → shrink** (section 3).
6. **Keyboard closes → grow back** and return to `Idle`.

Priority when two things happen at once: keyboard resize > `Smile` (result) > `Wave` > `Squint` > `Blink` > `Idle`. A lower one never interrupts a higher one.

### Events to wire

| App event | Fox response |
|---|---|
| Session start | `Wave` |
| 20 s with no input | `Squint` |
| Any input during `Squint` | cut to `Idle` (0.2 s blend), then `Smile` if it was a real action |
| Payment confirmed / check passed | `Smile` |
| Payment failed or blocked | no `Smile`; stay in `Idle`. Never celebrate an error. |
| Text field focused (keyboard up) | shrink to head-only |
| Text field blurred | grow back to full |

## 3. When the keyboard opens

The keyboard can take half the screen, so the fox must not fight the form for room.

- **Show the head only.** Crop to the head, ears and scarf collar. Drop the body and the waving paw, so `Wave` is not available in this mode (play `Smile` instead).
- Scale to roughly 25-30 % of the screen height. Keep it in a fixed corner or beside the field, never above the input where it could cover what the user types.
- Animate the resize over about 250 ms with ease-out (it should feel like it ducks down, not jump). Reverse it when the keyboard closes.
- Use the visual viewport height to detect the keyboard (the `visualViewport` API on web). Do not rely on a fixed pixel breakpoint.
- While typing, only the ear twitch and blink keep running. No `Squint` while the user is typing: typing is activity.
- Cropping is done in the app layout (a masked container or a second head-only artboard), not by editing the existing artboards.

## 3a. Chat page: the empty-box prompt

The fox's voice lives in the chat input's placeholder.

- **Empty box:** show the placeholder text **"yap here, I'll make it a transaction"**.
- **First letter typed:** the placeholder disappears at once. Do not fade it out slowly; it must never overlap what the user types.
- **Box emptied again** (the user deletes everything): the placeholder returns.
- Use the native `placeholder` attribute, not a styled label laid over the box. The browser then handles hiding and showing it correctly, including with IME and autofill.
- The label above the box ("Ask your agents") stays as the real accessible name. A placeholder is a hint, not a label, so it must not replace it.
- Style it in a muted colour that still meets contrast (at least 4.5:1) against the box background, and keep it in the same font and size as the typed text.
- Keep the text in sentence case with the lowercase "yap" as written; this is the fox's casual tone. Do not translate it into a formal prompt.
- The placeholder is static. The fox does not react to it, and it does not trigger `Squint`: an empty box with no input still counts toward the normal 20 s inactivity timer.
- When the keyboard opens and the fox shrinks to head-only (section 3), the placeholder stays as it is.

## 4. Design principles

- **Be a companion, not an interruption.** The fox never blocks content, never takes focus and never intercepts taps. It is decoration with meaning, so it stays out of the tab order.
- **Earn every movement.** Each animation maps to a real event. No random animations "for fun". Ambient motion is limited to blink, breathing and the ear twitch.
- **Anticipate, then act, then settle.** Each animation already eases in and out. Keep the blend between states short (about 150-250 ms) so changes never snap.
- **Timing sets the mood.** Quick and bouncy for good news (`Smile`, `Wave`), slow and held for doubt (`Squint`). Do not speed `Squint` up: the slow stare is what makes it read.
- **One thing at a time.** Never stack animations or start a new one before the current one finishes, unless a higher priority rule applies.
- **Respect the user's attention.** `Squint` is a gentle nudge, not nagging. Rate-limit it, and drop it entirely after about three plays in one session.
- **Honest emotion.** Smile only for real success. Never smile at a failure, a blocked payment or a risk warning. In those moments the fox stays neutral.
- **Trust matters here.** GraphPay is about asking before paying. `Squint` should feel like a careful friend ("are you sure?"), not an accusation. Do not show it during a payment decision, where it could be read as a verdict.
- **Calm on small screens.** Keep it modest in size, never above about a third of the screen when content is also showing.
- **Consistent character.** Same fox, same palette, same scarf across every screen. Do not recolour or restyle it per page.

## 5. Accessibility

- **Reduced motion.** If the user prefers reduced motion (`prefers-reduced-motion`), show a still pose, no waving or bouncing, no `Squint`. Allow only a gentle blink.
- **No information in the fox alone.** Anything the fox expresses must also appear as text (for example "Payment confirmed"). It is decorative: mark it `aria-hidden` or give it an empty alt.
- **No flashing.** Nothing flickers more than three times a second.
- **Pausing.** Stop the animation loop when the tab is hidden or the fox is off screen, to save battery and avoid motion the user cannot see.
- **Touch targets.** If the fox is ever tappable (for example to replay `Wave`), make it at least 44 by 44 px and give it a visible label.

## 6. Implementation notes

- Load the built `.riv` with a Rive runtime (for example `@rive-app/react-canvas`) and pick the artboard by name (`Wave`, `Smile`, `Blink`, `Idle`, `Squint`).
- Only one artboard shows at a time. Switch artboards for each state and play its state machine.
- Today the artboards are one-shot or loop on their own; the app decides when to switch. A cleaner next step is a single artboard with view-model triggers (`wave`, `smile`, `squint`) so Rive does the blending. Not built yet.
- Local unsigned builds are fine for development. A `.riv` with scripts that ships to the web must be built with `--publish` (needs `rive login`). The current file has no scripts.
- Keep the fox out of `apps/web` until the behaviour script above is agreed, then add a small `useMascot()` hook that owns the inactivity timer and the keyboard detection.

## 7. Open choices

- The 20 s inactivity delay and the 60 s repeat are starting values. Tune them in testing.
- Whether `Smile` also plays on the user's first interaction after a `Squint` or only on real successes.
- Head-only crop: a second head-only artboard, or a masked crop of the full one.
- Whether a tappable fox that replays `Wave` is wanted.
