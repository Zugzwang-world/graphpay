# Relay: payments (T1)

Updated 04:05 IST, Fri 6 Nov.

## In plain words

The till is live on Whitechain Sepolia since M2: our own checkout contract, set up for the real test USDT and verified on the explorer. Tonight's step (M3 part A) builds the two services that let an agent actually pay through it.

**Our own payment facilitator.** An agent pays by signing one message; the facilitator checks it and sends the transaction, paying the gas itself, so the agent needs no gas and no earlier approval. Because the facilitator pays for every transaction it sends, it is built to refuse anything doomed or forged *before* sending, cheapest checks first: is the message well formed and for our token, our contract and a known shop; did the payer really sign it; does the agent's ENS name pass the gate; will the payment really go through on-chain (the order is unpaid, the agent has the money, its spending rules allow it). Only then does it send. On top of that it limits how often one agent or one shop can pay, how much gas it may spend in a day, and it stops before its own balance runs low. A payment that breaks an agent's on-chain rules (revoked, expired, over its daily limit) is normally refused without a transaction, except a small daily allowance that is sent on purpose so the failure is recorded on-chain for the reputation graph. One kind of failure is never sent: a wallet claiming someone else's name, because that would write a failure into another agent's history.

**The shop's payment API.** A shop gives a free quote whose price always comes from the story's catalog, never from the request. Asking to pay returns the standard x402 "402 Payment Required" answer with exactly one way to pay; the agent signs it and asks again; the shop passes it to our facilitator and answers "paid" with the transaction. Asking again with the same signature answers "already paid" and moves no money, because the chain itself is the record (the shop keeps no database). The shop also checks that its own payout address is what its ENS name says before it offers a payment, and, when an agent's errand carries a request id, it writes its quote to Arkiv first so the agent can check the offer before it signs.

**Refusals become part of the graph:** each refusal of a proven payer is written to Arkiv as a readonly record, credited to an agent's name only when the paying wallet really belongs to it.

**What this means for the demo:** the whole flow ran end to end on a local copy of Whitechain, against the real deployed contract, the real test USDT and Permit2: an agent with no gas paid 4.80, a replay answered "already paid", the shop refunded 0.80, the agent re-ordered for 1.20, a forged signature was refused with nothing sent, and a revoked agent's attempt was recorded on-chain as `AGENT_REVOKED`. No real payment has been made yet: that is part B, which starts now that T2's ENS gate has merged. Nothing for the founder in this step.
