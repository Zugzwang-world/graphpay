## In plain words

`@graphpay_ethglobal/agentpay` is a small toolkit that lets any business take payments from AI agents in test USDT on Whitechain Sepolia, and lets any agent pay with one signature and no gas under a spending pass held on the blockchain. It has two sides, a customer's agent and a merchant, and two ready examples: a sweet shop and a fixed-fare cab ride. Prices are fixed in V1; letting a fare vary is V2.

**What now works for an outside developer.** They make an empty folder, run `npm install @graphpay_ethglobal/agentpay viem`, paste the README's example and run it. In a few seconds a local test copy of Whitechain starts on their own machine, a shop and a gasless agent are created with fresh keys, and the agent pays. We did exactly this from a packed copy of the package in an empty folder outside the repository, on Node 22: it printed `paid 4800000n`. The cab example passes the same way.

**Why a local copy.** Our deployed checkout lets only our own relayers settle payments, so a stranger cannot use it, by design: nobody can spend our gas or break the demo. For the real testnet, the package can deploy the developer's own checkout (`deployCheckout`) and they run their own relayer with their own key.

**Safety, as the founder required.**
- Whitechain Sepolia (1874) only. A client on another chain is refused when it is created, and the chain id is read before every signature and send.
- There is no default hosted facilitator or relayer. A merchant must be given a facilitator; the relayer runs with the developer's key.
- The relayer's anti-drain limits (balance floor, per-order cap, hourly count and value caps, per-payer rate, gas ceiling, one send at a time) are always on. A developer can change a limit to another real number, but zero, blank, NaN, infinity and unknown names are refused.
- A test fails the build if the package imports anything from our Arkiv, ENS or money-graph packages, or from any workspace package.
- The packed files hold no secret or keyed URL (the repository's own scanner is clean over the unpacked tarball).

**What the founder must do:** log in to npm when the Coordinator asks; the Coordinator publishes. Feedback goes to GitHub issues labelled `agentpay` and `feedback`, logged in the package's `FEEDBACK.md`.

## Technical

- **Rename:** `@graphpay/agentpay` to `@graphpay_ethglobal/agentpay` in package.json, imports, README, d.ts and T5's `packages/checkout-kit` (a mechanical change; no export changed). T5 was told.
- **Self-contained:** `src/vendor/` is generated by `packages/agentpay/scripts/vendor.mjs` from the contracts ABI, `typed-data.mjs` and the config's Whitechain defaults; a test fails if it drifts. `src/vendor/bytecode.mjs` is the creation code taken from the input of the checkout's deployment transaction (constructor arguments removed), so `deployCheckout` deploys the contract that is verified on the explorer. `dependencies` are viem, zod, `ai` and the MCP SDK only; the workspace packages are devDependencies for tests.
- **New API:** `deployCheckout`, `resolveLimits`, `assertClientChain`, and the subpath `@graphpay_ethglobal/agentpay/sandbox` (`startSandbox`: spawns `anvil --fork-url` on a loopback port, refuses a fork that does not answer 1874, deploys a checkout, gives fresh keys WBT and the buyer test USDT by writing storage on the fork only).
- **Tests:** 52 offline (11 new in `test/publish.test.mjs`: vendor sync, self-containment, lane, no secrets, chain refusal at creation and before signing, role overlap, limits cannot be switched off, no hosted defaults); 18 fork, including both shipped examples run as plain scripts.
- **Pack check (Node 22.23.4):** `pnpm pack` gives a 75 KB tarball of 32 files; `npm install` of the tarball plus viem in an empty folder; the README's code, the copied example and the cab example all pass there.
- **Records:** `scripts/check.mjs` gains one exemption (the generated defaults file); T1's and T4's packages and the contract are untouched.
- **Open risks:** the sandbox needs Foundry (`anvil`) and a reachable public Whitechain RPC; the real-testnet path with a developer's own checkout is covered by the fork test (the same bytecode) but not by a real deployment, which would need a funded key.
