# ACCEPTANCE TESTS (the replication suite)

At the event these become one command, **`pnpm acceptance`**, which runs every test on the real networks and writes `ACCEPTANCE_REPORT.md` with every result, transaction hash and explorer link (`PROMPTS/13-acceptance.md`). `pnpm acceptance --dry-run` prints the plan and the expected spend and sends nothing; `--only C,D` runs a subset.

Rules: a test passes only on its exact criteria. A test that cannot run for an external reason reports `blocked` with the reason, never `pass`. Where the lab measured a value, it is given with a tolerance; gas tolerances are ±15% (same contract, same chain), Arkiv gas ±25% (the merged model is bigger), times ±25%. Tests that need a one-shot resource (a disposable agent, a re-registration) create it first and say so. Acceptance uses its own buyer agent `acceptance.vitalik.graphpay.eth` (policy cap 6.00/day) wherever a test pays, so `payer.vitalik`'s cap stays fresh for the stage.

**Report format.** Header: date and time (IST and UTC), commit, networks and chain ids, token mode (USDT or stand-in), checkout address. Then a summary table (id, name, result, key value against expected, evidence link), then one section per test with its evidence.

## Expected spend of one full run (lab receipts, approximate)

Whitechain: about 15 transactions, under 0.02 WBT (lab gas for the listed tests is about 0.013 WBT; relayer, renewer, merchant, policy writer). Sepolia: about 10 transactions (two disposable agents, two kills, the scoped-role write), negligible at 2026-11-04 gas prices. Rabdi: about 20 mirror batches plus a few recorder edges, under 0.05 tGLM. Token moved, by the acceptance agent unless noted: C2 4.80, C3 re-order 1.20 and renewal 0.40 (VITALIK), C4 0.40 (scout, refused on-chain, no transfer), B6 and E7 0.40 each (disposable agents), one 4.80 test USDT payment (separate checkout) that is the evidence for both C7 and E3; refunded: C3 0.80 and E6 0.80. The acceptance agent's 6.00 per UTC day is exactly C2 + C3, after which C4(b) is over the cap by construction. Section E is read from the M12 counting run's run file (no second payment); when test USDT arrives, `usdt-ready --go --yes` makes **one** 4.80 payment as `acceptance.vitalik` on the USDT checkout (its cap there is separate from the stand-in checkout's); C7 and E3 both read that transaction, and `pnpm acceptance` never pays in USDT itself. Run time: about 15–25 minutes (Sepolia blocks and Rabdi writes dominate).
