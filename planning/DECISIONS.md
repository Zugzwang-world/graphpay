# DECISIONS to adopt at the event

One line per decision plus the reason. Part A lists the lab's ADRs (ADR-0001 to ADR-0023; there is no ADR-0014) as the event should adopt them, with later corrections folded in. Part B lists decisions this pack proposes for the event build; record each as an ADR in the event repo when it is taken (or overturned). The event repo writes its own ADRs: these are the knowledge, not the files.

## B. Proposed for the event (decide at the named milestone; record as ADRs)

| id | decision | reason | when |
|---|---|---|---|
| E-1 | Host the facilitator and the shop API as Vercel Functions behind the passcode and bearer token (as the lab did), and give scheduled renewals a **second relayer key** (`RENEWER`) so scripts and the hosted facilitator never share a nonce stream | The brief puts hosting on Vercel (M4); in-memory limits are per instance, so the on-chain caps and the 0.3 WBT relayer floor are the real bounds; nonce clashes came from sharing one relayer key | M2 (grant the role), M4 |
| E-2 | The mirror is the **single W_LEDGER writer** (nodes, chain-derived edges, tallies, links, checkpoints), run as **exactly one long-lived workers process** (with the ENS watcher) on the founder's Mac, polling every 2 s; it refuses to start if another instance's heartbeat is fresh; a Vercel cron fallback gated by that heartbeat is a stretch. Off-chain records (facilitator refusals, refund requests) are written create-only by Vercel recorder routes from **W_SYNC** and folded into tallies by the mirror | Edge and tallies must land in one atomic batch, so one wallet writes both. Overlapping writers are **not** safe: a batch built on a stale read can land at the next confirmed nonce and overwrite absolute tallies (ADR-0020, ADR-0023: one serialised writer). The hosted facilitator cannot reach a local process, hence the create-only recorder | M11 |
| E-3 | Merchant keys for kesar-kingdom (and the trap and runner-up for the lifecycle beats) are set on Vercel as Sensitive values, used only by passcode-gated merchant routes (dispatch, partial refund, full refund) | The merchant screen needs those buttons live; refunds are bounded by the merchant's approved float and the order's paid amount | M4, M15 |
| E-4 | Arkiv lifetimes: real rows 30 days (extend weekly if judging runs longer), synthetic rows 14 days | `max()` roughly triples a create; the event only needs rows to outlive judging | M7 |
| E-5 | Adopt the renewal-id top-bit fix in the contract; the one-off id derivation from payer and witness only if M1 has time | Closes the renewal-squatting grief cheaply; the other grief vectors risk no funds on a testnet | M1 |

The lab's other wallets are not used; their spare test tokens were swept into FUNDER before the event; disclose it | Fewer pre-event items in the event repo and nothing tied to lab activity; the ENS root can only be built by its owner, and FUNDER holds the faucet tokens | M0 |
